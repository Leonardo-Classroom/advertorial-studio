{% comment %} Blocking progress overlay for the slow operations. Written with this tag, not the hash-brace form: that one is single-line only, and a multi-line version of it is not treated as a comment at all — it ships to the page as literal text, which is how this very block first appeared on screen. Any commentary spanning lines belongs here. Generation runs synchronously inside the request — a staged run takes 91s at the median and has been seen at 403s — so without this the page simply sits there. Two things go wrong then: the user clicks something else and loses the run, or decides it has crashed and submits again, which starts a second run and pays for it twice. The steps are driven by a timetable built from the recorded stage medians of 172 real runs, not by server progress: nothing here can report actual progress, because the request that would answer is the one being waited on. So the display is deliberately honest about what it knows — it names the step that should be running and counts real elapsed seconds, but never shows a percentage and never claims to be finished. Past the expected total it says so and keeps counting, rather than freezing on a last step that has silently stopped meaning anything. {% endcomment %}
